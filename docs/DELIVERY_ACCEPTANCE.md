# AIGC Production OS｜交付自审机制

这份文件是交付门槛，不是宣传文案。任何一项 P0 失败，都不能把当前版本交给用户作为“可用版”。

## P0 交付门槛

- 能通过项目根目录的 `启动桌面App.command` 启动 Electron 桌面端。
- 创建或打开旧项目不会删除项目、文档、资产和生成记录。
- “继续工作”进入工作台或当前阶段文档，不落到与制作无关的概览页。
- 工作台能显示第几阶段 / 共几阶段、百分比、当前状态和返工风险。
- 阶段状态支持自动判断和手动标注，手动标注不会污染自动状态。
- 工作台按“分析 → 确认 → 执行 → 审核”保存正式执行状态；未确认时执行入口不可用，审核结论会写回阶段状态。
- 参考图、资产、镜头、生成任务和文本说明在项目范围内继续复用。
- 参考图用途、证据拆解、Visual DNA 和迁移提示词写入项目配置；旧版缓存可兼容读取。
- 生成失败能被看见，生成成功能进入项目资产和任务记录。
- 生成输出目录可由用户指定，复制失败不能破坏原始项目媒体库。
- 2019 Intel Mac 使用 `darwin-x64` 运行文件，不依赖 ARM 二进制。

## 每次交付前执行

```bash
pnpm delivery:check
```

脚本会依次检查：

1. 必要入口和核心文件是否存在。
2. 前端 TypeScript 与生产构建。
3. 生产流程、模板、项目概览测试。
4. Electron preload 编译。
5. 本地 Go 服务测试。

## 人工烟囱测试

1. 双击启动脚本，确认桌面窗口出现。
2. 新建一个测试项目，进入“继续工作”。
3. 在工作台切换阶段，确认空阶段灰置、有内容阶段可进入。
4. 在当前阶段备注中写入一句话，关闭并重新打开项目，确认备注还在。
5. 打开“参考图拆解与迁移”，导入两张图，为两张图分配不同用途。
6. 生成一张图片，确认任务中心、资产库和指定输出目录都能找到结果。
7. 将阶段标记为“需修改”，确认首页和工作台显示风险，而不是把项目伪装成已完成。
8. 打开一个旧项目，确认名称、文档、资产和历史任务不丢失。

### 本轮交付新增的验收点

9. 在项目首页“制作控制台”记录一次 QC，刷新项目后确认记录仍在。
10. 记录同一个资产的多个版本，确认自动生成 `V01 / V02 / V03`，历史版本不被覆盖。
11. 在“沉淀复盘”中写入结论、可复用 Prompt 和规则，确认它们属于当前项目共享记忆。
12. 打开设置 → API 密钥，确认“本机模型配置状态”只显示可用性，不显示任何 Key。

## 当前版本的边界

- GPT-5.6、GPT Image 2、Nano Banana 的密钥不会写入源码；模型是否可用取决于本机安全配置和服务端连通性。
- 远程插件、云同步、多人协作和自动发布不属于本次本地桌面交付范围。
- 视觉模型的真实连通性仍以本机安全配置和服务端返回为准；界面不会伪造“已连通”。
- QC、版本历史、复盘和共享记忆已落入项目配置；更复杂的批量 QC、跨项目 Skill 导入后续再扩展。
